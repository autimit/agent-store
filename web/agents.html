Uma loja.
Duas entradas.

A pessoa escolhe pela vitrine. Um agente pode consultar o mesmo catálogo e iniciar um checkout pela API. Os dois caminhos passam pelas mesmas regras de estoque e preço.

DEMONSTRAÇÃO LOCAL · Nenhuma cobrança ou entrega real.

Comece pelo contrato.

Interface HTTP documentada em OpenAPI 3.1. Os preços são inteiros em centavos de BRL. Consulte disponibilidade antes de criar um checkout.

Contrato OpenAPI ↗Identidade e políticas ↗Guia textual ↗Catálogo JSON ↗

Da intenção ao pedido.

  1. Descobrir. Consulte produtos, cores, imagens e tamanhos em GET /api/v1/products.
  2. Conferir. Use GET /api/v1/variants/{id}/availability. A consulta não reserva.
  3. Cotar. Calcule frete com POST /api/v1/shipping-quotes usando itens e CEP. Envie itens e a opção shipping para POST /api/v1/quotes. O servidor calcula o preço.
  4. Confirmar com a pessoa. Só então crie o checkout com POST /api/v1/checkouts e Idempotency-Key, incluindo shipping e delivery com contato e endereço fictícios. O CEP de entrega deve ser o mesmo usado para cotar. Reserva de 15 minutos.
  5. Testar a conclusão. Com autorização explícita para a simulação, envie POST /api/v1/checkouts/{id}/simulate-payment. Isso cria um pedido fictício, sem movimentar dinheiro.

Guarde o access_token retornado pela criação. As operações do checkout exigem Authorization: Bearer <access_token>. Reutilize a chave de idempotência e o mesmo corpo se houver falha de rede na criação.

Um primeiro pedido HTTP.

curl http://127.0.0.1:8091/api/v1/products

curl -X POST http://127.0.0.1:8091/api/v1/quotes \
  -H 'Content-Type: application/json' \
  -d '{"items":[{"variant_id":"aut-oliva-m","quantity":1}]}'

O que este experimento prova.

Uma interface independente de modelo, um estoque compartilhado entre canais, reserva transacional e conclusão idempotente de uma compra simulada. Pedidos e reservas sobrevivem ao reinício do processo.

Esta entrega oferece uma API HTTP. Não inclui servidor MCP, A2A, descoberta automática em agentes pessoais, pagamento real ou comprovação de operação em escala. O Haseo poderá usar essa API por um conector.
